# خطة تطبيق تصميم الجوال (v2 — النمط الجديد)

مرجع التصميم: `Tasks Mobile Redesign.dc.html` (ثمان شاشات بعرض 390px، اتجاه RTL، خط Cairo).
الهدف: نقل النمط الجديد إلى `apps/web` مع ما يلزمه من تعديلات في `apps/api` و`packages/types`.
كل مرحلة قابلة للدمج وحدها، ومرتّبة بحيث لا تعتمد مرحلة على ما بعدها.

## القرارات المعتمدة

| القرار | المعتمد |
|---|---|
| فئات الحالة | «تم التنفيذ» = `DONE` · «انتهى» = فئة جديدة **`CLOSED`** — والتقارير تجمعهما كمنجَز |
| معنى «انتهى» | سُلّمت وتم التأكّد منها |
| عدّ المنجَز | عند **أول** دخول إلى «تم التنفيذ» — لا تُحسب مرتين |
| متوسط زمن الإنجاز | يُقاس حتى «تم التنفيذ» فقط |
| عمود «انتهى» في اللوحة | يعرض آخر **30 يومًا** فقط |
| من ينقل البطاقة | أي عضو في اللوحة — بلا موافقة على الحالة النهائية |
| موعد تسليم اللوحة | اختياري، ويظهر كصف مستقل في تقرير المتأخّرات |
| التقارير | `ADMIN` فقط |
| شاشة «مهامي» | مطلوبة — أولوية عالية |
| شاشة البداية | آخر شاشة فُتحت |
| «حفظ كمسودة» | **محذوف** |

**أولوية التنفيذ:** شاشة اللوحة والنقل بين الحالات ← شاشة اللوحات ← تفاصيل البطاقة والإسناد.

## 1) المخطّط والعقود المشتركة

| الملف | التغيير |
|---|---|
| `apps/api/prisma/schema.prisma` | إضافة `dueDate DateTime?` إلى `Board` + مِهجرة (`npx prisma migrate dev`) |
| `packages/types/src/domain.ts` | إضافة الحقل لمخطّط `Board` |
| `packages/types/src/requests.ts` | إضافة الحقل لـ `CreateBoardRequest` و`UpdateBoardRequest` |
| `apps/api/prisma/schema.prisma` | إضافة قيمة `CLOSED` إلى `StatusCategory` |
| `apps/api/src/boards/board-templates.ts` | الترتيب المعتمد: جديد ← جاهز للتنفيذ ← قيد التنفيذ ← تم التنفيذ (`DONE`) ← انتهى (`CLOSED`) |
| `docs/02-domain-model.md` · `docs/09-list-status-templates.md` | تحديث في نفس الـ PR (سياسة `08-maintaining-docs.md`) |

**موعد تسليم اللوحة اختياري:** لا تظهر الشريحة إطلاقًا عند `null` — لا نص بديل ولا حقل فارغ.

**`CLOSED` فئة جديدة لا حالة نظام:** كل ما يعتمد اليوم على `DONE` (التقارير، «غير منجَز») يجب أن يعالج `DONE | CLOSED` معًا. تُراجَع كل مواضع `statusCategory === 'DONE'` في `apps/api/src` وتُستبدل بدالة واحدة `isCompleted(category)`.

## 2) أساس الواجهة على الجوال

- `apps/web/index.html`: تحميل خط **Cairo** فعليًا (`tailwind.config.js` يُعرّفه اليوم دون `<link>`).
- `tailwind.config.js`: تعريف ألوان النمط كـ tokens بدل تكرار قيم hex في المكوّنات:
  - `ink #23232A` · `muted #8B8B95` · `line #EAE8E3` · `surface #FFFFFF` · `canvas #F7F6F3`
  - `accent #4A6FD4` / `accent-soft #EAEFFB`
  - حالات: `#A9AEC0` جديد · `#6E8AD8` جاهز · `#E0A34A` قيد التنفيذ · `#59B08A` تم التنفيذ · `#8B8B95` انتهى
  - تنبيه: `#C0503C` / `#FBE9E7`
- **الأنصاف والمسافات:** بطاقات 20–22px، أوراق سفلية 30px، حقول 16–18px. حد أدنى لمساحة اللمس **44px**.
- `AppShell` جديد بشريط سفلي (اللوحات · مهامي · التقارير · حسابي)، يُخفى على الشاشات الكبيرة. رابط «التقارير» يبقى محكومًا بدور `ADMIN`.
- **شاشة البداية:** يُحفظ آخر مسار مفتوح في `localStorage` ويُستعاد عند التشغيل، مع رجوع إلى «اللوحات» إذا كان المسار غير صالح أو فقد المستخدم صلاحيته عليه.

## 3) شاشة اللوحات

- `BoardsListPage.tsx`: بطاقة لوحة جديدة — الاسم، الوصف، شارة الدور (مالك/عضو)، شريحة موعد التسليم الاختيارية، شريط تقدّم مجزّأ (منجَز/جارٍ/متبقٍ)، صور الأعضاء المتراكبة، وعدّاد «n مهمة · m مكتملة».
- نموذج الإنشاء ينتقل من الصف العلوي إلى **ورقة سفلية** (الاسم، القالب، موعد التسليم الاختياري).
- **الخادم:** `GET /boards` يحتاج إرجاع `memberCount` و`cardCount` و`doneCount` — تُحسب عبر `groupBy` واحد في `BoardsService.list` دون استعلام لكل لوحة.

## 4) شاشة اللوحة والنقل بين الحالات

- `ListColumn.tsx`: عمود بعرض 318px داخل حاوية `scroll-snap-type: x mandatory`، وشريط تبويبات الحالات فوقه (الاسم + العدد).
- `CardItem.tsx`: وجه البطاقة الجديد — العنوان، قفل `isRestricted`، شريحة موعد التسليم (حمراء عند التأخّر)، `☑ n/m` للمهام الفرعية، صور المسؤولين، وزر أيقونة **«←»** ينقل للحالة التالية.
- مكوّن جديد `MoveCardSheet.tsx`: يُفتح بالضغط المطوّل، يعرض الحالات الخمس بترتيبها (الحالية معطّلة، التالية مميّزة) + «فتح البطاقة» و«حذف».
- كلا المسارين يستدعي `PATCH /cards/:id { targetListId }` **بدون `move`**، فتُوضع البطاقة في نهاية القائمة الهدف (`05-boards-lists-cards.md`).
- بطاقات آخر حالة لا تملك «تالية» → يختفي زر السهم ويبقى الضغط المطوّل.
- **النقل متاح لأي عضو** في اللوحة، ولا يحتاج الوصول إلى «انتهى» أي موافقة — `assertMembership` وحدها كافية.
- **عمود «انتهى»:** يعرض البطاقات التي دخلته خلال آخر 30 يومًا فقط، مع صف «عرض الأقدم» أسفله. يحتاج الخادم مُرشِّحًا `closedSince` في `GET /boards/:id` كي لا يُرسل تاريخ اللوحة كاملًا.
- **`dnd-kit`:** يبقى كما هو لسطح المكتب. على اللمس يُضبط `activationConstraint` (تأخير + مسافة) كي لا يتعارض السحب مع التمرير الأفقي ولا مع الضغط المطوّل.
- **الخادم:** عدّاد المهام الفرعية على وجه البطاقة يحتاج `subtaskDone`/`subtaskTotal` ضمن استجابة البطاقة (اليوم تُجلب المهام الفرعية بطلب منفصل لكل بطاقة).

## 5) تفاصيل البطاقة والإسناد

- `CardDetailModal.tsx` → **ورقة سفلية** بارتفاع 96%: رأس ثابت (إلغاء · شريحة الحالة · حفظ)، ثم العنوان وشريحة موعد التسليم وسطر «أنشأها … · اللوحة»، ثم الوصف، المسؤولون، المهام الفرعية بشريط تقدّم، تقييد الوصول، والسجل.
- حُذف صندوق «المهام الفرعية n/m» المكرَّر — العدّاد داخل قسم المهام الفرعية وحده.
- مكوّن جديد `AssigneePickerSheet.tsx` (بحث + اختيار متعدّد) يخدم البطاقة والمهمة الفرعية معًا:
  `PATCH /cards/:id/assignees` و`PATCH /subtasks/:id/assignees` — **استبدال كامل ذرّي**، وكل مُسنَد يجب أن يكون عضوًا في اللوحة.

## 6) صفحة إضافة مهمة

- مسار جديد `/boards/:boardId/cards/new` بدل حقل «+ إضافة بطاقة» داخل العمود.
- الحقول: العنوان، اللوحة والحالة (تحدّد `listId`)، الوصف، موعد التسليم باختصارات (اليوم / غدًا / تاريخ آخر)، المسؤولون، المهام الفرعية، مفتاح تقييد الوصول.
- **«حفظ كمسودة» محذوف** — زر واحد: «إضافة المهمة».
- **تسلسل الطلبات:** `POST /lists/:listId/cards` ← `PATCH /cards/:id/assignees` ← `POST /cards/:cardId/subtasks` لكل مهمة فرعية. حالة تحميل واحدة، وتراجع واضح عند فشل أي خطوة بعد الإنشاء.
- البطاقة الجديدة تُضاف في **نهاية** القائمة دائمًا (سلوك الخادم الحالي).

## 7) التقارير

**الخادم** (`apps/api/src/reports/*` و`packages/types/src/reports.ts`):

| الإضافة | المصدر |
|---|---|
| تقسيم يومي للمنجَز خلال النافذة | `CardActivity` نوع `MOVED` — **أول** دخول إلى قائمة `DONE` لكل بطاقة (`DISTINCT ON (cardId)`) |
| مقارنة بالأسبوع السابق | نافذة زمنية ثانية بنفس المنطق |
| متوسط زمن الإنجاز (من الإنشاء إلى `DONE`) | `CardActivity` — يتوقّف عند «تم التنفيذ»، ولا يشمل زمن التأكّد والتسليم |
| لوحات تجاوزت موعد تسليمها | `Board.dueDate` — صف مستقل أعلى تقرير المتأخّرات |

**الواجهة** (`ReportsPage.tsx`): تبويبات (المُنجَز · نظرة عامة · المتأخّرة · عبء العمل)، بطاقة الرقم الكبير مع الأعمدة اليومية، «أكثر من أنجز» ومتوسط الزمن، التوزيع حسب اللوحة، قائمة آخر ما أُنجِز، ثم اللوحات المتأخّرة كصفوف مستقلة تليها المهام المتأخّرة بمقدار التأخّر، وعبء العمل بشريط مزدوج يفصل المتأخّر عن المفتوح.

## 7.1) شاشة «مهامي»

مسار `/my-tasks` — الشاشة الثانية في الشريط السفلي، وأولوية عالية.

- **المحتوى:** المهام المُسنَدة لي + المهام الفرعية المُسنَدة لي، **المتأخّرة أولًا**، ثم **مجمّعة حسب اللوحة**.
- المهمة الفرعية تظهر **صفًّا مستقلًا يحمل اسم بطاقتها الأم** — لأنها قد تكون مُسنَدة لي دون أن تكون البطاقة نفسها كذلك.
- تُستثنى البطاقات في `DONE` و`CLOSED`.
- **الخادم:** نقطة جديدة `GET /my-tasks` تجمع `CardAssignee` و`SubtaskAssignee` للمستخدم الحالي عبر كل اللوحات، وتحترم `isRestricted`. ليست تقريرًا ولا تخضع لـ `AdminGuard`.
- **التصميم:** الشاشة مصمّمة في `Tasks Mobile Redesign.dc.html`.

تحديث `docs/11-reports.md` بالحقول الجديدة.

## 8) ما بعد الدمج

- مراجعة مساحات اللمس (44px) وتباين الألوان على الشاشات الصغيرة.
- إضافة مصطلحَي «موعد تسليم اللوحة» و«انتهى (`CLOSED`)» إلى معجم `docs/01-overview.md`.
- التحقّق يدويًا من: النقل بالسهم، النقل بالضغط المطوّل، السحب على سطح المكتب — وثبات الترتيب بعد إعادة تحميل الصفحة.
- التحقّق من رسائل الأخطاء: فشل خطوة بعد إنشاء المهمة، وإضافة عضو ببريد غير مسجَّل.
